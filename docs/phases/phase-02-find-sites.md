# Phase 2. Find every site

## Goal

Build the scanner step that finds all TapeOut sites on X Layer and saves them in the Site table.

## Start when

- Phase 1 is done.

## What to build

1. **Choose a method.** Try Method 1 first. If your connection refuses it, use Method 2.
   - **Method 1:** read the public "file added" records (`FileSet`) from the site store. Every site space that appears has a site. This needs a connection that returns past records.
   - **Method 2:** walk through the processors (`cpuCount`, `cpuAt`), then through each processor's circuits, and ask which have an open site space (`isOpened`, `accountOf`) that holds at least one file (`pathCount`). TapeBrowser's open code shows one way to walk the numbers.
2. **Save each site once** with its address, chain and site space.
3. **Mark each site active or not active** using the site store's activity check.
4. **Make it safe to rerun.** Running it again must update existing sites, not create copies.
5. **Record how many sites were found** each time it runs.

## Done when

- All X Layer sites are saved.
- Your count is close to another public list (TapeWeb or TapeBrowser's "all sites").
- Running it twice gives the same count, with no duplicates.
- Each site is marked active or not active.

## Watch out

- Many public connections refuse past records. Switch to Method 2 instead of fighting it.
- New sites appear over time. The count will not match other lists exactly. Close is enough.
- Start with X Layer only. BNB Chain comes after the whole product works.

- **Activity meaning and verification:** Discovery separately establishes an opened circuit (`isOpened`/`accountOf`) and a non-empty site space (`pathCount > 0`). `active` is the TapeOut DomainBinding payment-activation result: `isLive(canonicalName, container) OR isContainerLive(container)`, per TapeKit SPEC §3.4. It does not mean merely that a container exists, that a circuit is open, or that files exist. The scanner only classifies inactive when both calls successfully decode to `false`; an unreadable result is an error and is not silently stored as inactive. In each complete scan, `sitesChecked` equalled `sitesFound` and the failure count was zero.
